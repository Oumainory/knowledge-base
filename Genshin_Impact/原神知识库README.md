# 原神知识库

本库整理《原神》的剧情、世界观、角色、物品故事与相关文本，使用 Obsidian Markdown 保存。知识库以可阅读、可检索、可建立关联的原文资料为主体，不是养成攻略或数据攻略库。

## 一、知识库范围

本库主要收录：

- 主线、传说、世界、活动、委托等任务原文及剧情对话；
- 角色故事、角色语音、角色相关文本；
- 武器故事、圣遗物故事、书籍原文；
- 游逸旅闻、家园对话、剧诗台词等补充文本；
- 系列任务的导览页，以及用于阅读顺序或内容索引的辅助页面。

本库重点保存剧情和设定信息。攻击力、技能数值、掉落、奖励、获取方式、培养建议等攻略内容不属于本库主体；在故事类文件中，这些与剧情无关的内容通常会被省略。

## 二、权威层级和第三方解读

知识库将游戏文本和剧情解读分开保存，并明确区分它们的权威性：

| 层级 | `layer` | 内容 | 用途 |
|---|---|---|---|
| 1 | `原文` | 游戏内文本、官方设定和任务正文 | 事实判断和最终依据 |
| 2 | `第三方解读` | B 站 UP 主对剧情的整理、分析、考据或推测 | 辅助检索、补充背景、提示可能遗漏的关联 |
| — | `导览` | 系列任务目录、阅读顺序和索引 | 导航，不单独作为事实证据 |

第三方解读不是官方设定。它可以帮助 Copilot 找到被向量检索遗漏的剧情关联，但不能替代游戏原文。Copilot 处理这类内容时应遵守以下顺序：

1. 游戏原文存在时，以 `layer: 原文` 的内容为准；
2. 原文没有直接回答、或需要整理线索时，才使用 `layer: 第三方解读` 作为补充；
3. 第三方解读与游戏原文冲突时，原文优先，并明确指出存在解读差异；
4. UP 主的分析、考据和推测必须标为“解读”或“推测”，不能改写成官方事实；
5. Copilot 自己推导出的内容也应与原文和第三方观点区分开。

第三方内容建议放在独立目录，并通过 `对应原文` 和 `解析对象` 连接到正式知识条目：

```text
11_第三方解读/
└─ UP 主或主题/
   └─ 视频标题.md
```

### 活动任务的文件结构

活动任务按照版本或活动主题分组；有系列关系的任务继续放入系列文件夹：

```text
04_活动任务/
└─ 版本或活动主题/
   └─ 系列任务/
      ├─ 系列任务.md
      ├─ 01. 第一项任务.md
      ├─ 02. 第二项任务.md
      └─ 03. 第三项任务.md
```

系列文件夹本身不需要编号。编号只用于表示系列内任务的阅读顺序，任务文件使用 `01.`、`02.`、`03.` 等前缀。没有明确系列关系的活动内容，可以直接放在对应的版本、地区或活动主题文件夹中。

系列任务页是导览页，正文中的任务列表使用 Obsidian 双链指向具体任务文件；具体剧情仍以编号任务文件为准。

### 补充资料

衣装、风之翼、地理志、怪物介绍、材料、任务道具、摆设、摆设套装及卡牌文案、角色邮件、过场提示和名片文本，补充任务正文之外的世界观线索。

完整重复的文本通过导览链接到已有笔记；部分重复的段落链接回已有原文，其余内容保留在补充条目中。资料中的版本、触发条件和选项分支应结合正文阅读。

补充条目中的来源备注用于解释条件；编辑考据与推测不能提升为游戏事实。

## 四、Front Matter

### 公共字段

大多数知识条目使用以下字段：

```yaml
游戏: "原神"
layer: "原文"          # 原文、导览或第三方解读
type: "任务原文"
涉及实体: []            # 正文中出现并建立双链的相关实体
```

`layer: 原文` 表示正文资料；`layer: 导览` 表示系列任务等索引页面。`type` 用于区分内容类型，`涉及实体` 用于从人物、地点、物品、任务和其他设定之间建立检索关系。

### 第三方剧情解读

B 站视频转写或整理后的剧情解读使用独立的类型和来源字段。它们用于引导检索、串联线索和补充理解，不与官方原文混合：

```yaml
游戏: "原神"
layer: "第三方解读"
type: "剧情解读"
权威等级: 2
来源平台: "哔哩哔哩"
来源UP主: ""
视频标题: ""
来源链接: ""
解读性质: ["事实整理", "分析", "推测"]
解析对象: []
对应原文: []
涉及实体: []
```

`权威等级: 2` 表示它低于游戏原文的一级；游戏原文为最高依据。`解析对象` 用于说明解读针对的任务、角色、地区或设定，`对应原文` 用于指向库内可以核对的官方文本。无法确认的内容应保留为分析或推测，不要写成确定事实。

第三方解读正文开头建议保留醒目的说明：

```markdown
> [!warning] 权威性说明
> 本文是 B 站 UP 主的剧情解读，不是游戏原文。涉及事实时优先以 `layer: 原文` 的笔记为准；本文中的分析和推测仅作辅助参考。
```

为了方便 Copilot 使用，正文最好分开写“核心观点”“原文依据”“解读与推测”，并在“原文依据”中链接对应的游戏文本。

### 任务原文

```yaml
任务类型: "魔神"
所属地区: []
版本实装: ""
开放等级: ""
任务条件: ""
所属系列: ""
所属幕: ""
任务编号: ""
涉及角色: []
相关活动: []
相关道具: []
相关成就: []
前置任务: []
后续任务: []
```

任务类型按知识库中的统一分类记录：魔神、传说、世界、活动、委托和交互事件等。必要时会保留 `原始任务类型`，用于说明源资料中的原分类。任务之间的前置、后续关系以及所属系列关系使用双链或结构化字段保存。

任务正文通常包括任务描述、任务剧情、任务步骤、旁白、角色对话、玩家选项、分支剧情和提示。

### 角色故事与角色语音

角色故事记录角色的基础设定、角色详细、角色故事、神之眼、冒险笔记、官方介绍及命之座名称等文本。角色语音按语音类型分组保存，重点保留角色台词。

常见字段包括：

```yaml
所属角色: ""
元素属性: ""
武器类型: ""
实装版本: ""
```

### 书籍原文

书籍保留游戏内可阅读的原文。多卷书籍按卷拆分，每卷单独成文，并通过书名、卷数、卷名和涉及实体与其他条目关联。

```yaml
书名: ""
卷数: ""
卷名: ""
体裁: ""
```

### 武器故事与圣遗物故事

这两类文件以背景故事、描述和世界观信息为主。武器数值、技能效果、获取途径以及圣遗物两件套、四件套效果等攻略数据不作为故事正文保存。

### 其他文本

家园对话、剧诗台词、游逸旅闻和其他补充文本按照其实际来源归档，并保留对应的 `type`、人物、地区、活动或相关实体信息。

万国诸卷拾遗按地区保存。条目使用 `type: "词条原文"` 和 `词条: "万国诸卷拾遗"`，并通过 `来源页面`、`来源分区`、`来源链接` 保留原文出处。

NPC 图鉴按规范 NPC 详情页身份合并为一条笔记，覆盖 11 个实际内容分区。条目使用 `type: "NPC图鉴"`；`图鉴分区`、`所属地区`、`地点`、`状态`、`来源页面` 和 `来源链接` 记录其分区归属与来源。`商店`、`赠礼` 是图鉴分区，不是所属地区；“全部”、低负载模式和统计页等辅助页面不单独生成 NPC 笔记。

## 五、正文与链接约定

- 角色对话使用 Markdown 列表或加粗角色名表示；
- 玩家选项使用 `> **[玩家选项]**：…`；
- 效果、提示和分支剧情使用引用块或对应的小标题表示；
- 任务、人物、地点、物品和其他知识条目之间优先使用 `[[页面名]]` 双链；
- 黑幕、折叠框、颜色、注音和网页排版标记转换为可直接阅读的 Markdown 文本；
- 正文尽量保持源资料的叙事顺序和原意，不额外加入未经标注的剧情推断。

## 六、使用方式

可以从目录按任务类型浏览，也可以从系列任务导览页进入具体任务。进行检索时，通常可以结合以下字段和关系：

- `type`：按任务、角色、书籍、武器、圣遗物等内容类型筛选；
- `所属系列`、`任务编号`：还原任务线和阅读顺序；
- `涉及角色`、`涉及实体`：查找人物、地点、物品和事件之间的关联；
- `版本实装`、`所属地区`：按时间或地区定位剧情；
- `layer: 第三方解读`：查找辅助性分析，再回到 `layer: 原文` 核对事实。
