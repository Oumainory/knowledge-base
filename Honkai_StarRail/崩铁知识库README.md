# 崩铁知识库

本库整理《崩坏：星穹铁道》的剧情、世界观、角色、物品、模拟宇宙与相关文本，使用 Obsidian Markdown 保存。知识库以可阅读、可检索、可建立关联的原文资料为主体，不是养成攻略或战斗数据攻略库。

## 一、知识库范围

本库主要收录：

- 开拓任务、开拓续闻、同行任务、冒险任务、日常任务、活动任务和交互事件；
- 角色故事、角色语音；
- 光锥故事、遗器故事、书籍原文；
- 模拟宇宙中的奇物、事件和权杖，以及差分宇宙中的方程；
- 敌对物种、派系、星神和专有名词等世界观条目；
- 系列任务导览页和大型词条的章节化内容。

本库重点保存剧情、设定和文本信息。角色与敌人的战斗数值、技能效果、抗性、掉落、奖励、获取方式、培养建议等攻略内容不属于本库主体；在故事类文件中，这些与剧情无关的内容通常会被省略。

## 二、权威层级和第三方解读

知识库将游戏文本和剧情解读分开保存，并明确区分它们的权威性：

| 层级 | `layer` | 内容 | 用途 |
|---|---|---|---|
| 1 | `原文` | 游戏内文本、官方设定和任务正文 | 事实判断和最终依据 |
| 2 | `第三方解读` | B 站 UP 主对剧情的整理、分析、考据或推测 | 辅助检索、补充背景、提示可能遗漏的关联 |
| — | `导览` | 系列任务目录、阅读顺序和索引 | 导航，不单独作为事实证据 |

第三方解读不是官方设定。它可以帮助 Copilot 找到被向量检索遗漏的剧情关联，但不能替代游戏原文。Copilot 处理这类内容时应遵守以下顺序：

1. 游戏原文存在时，以 `layer: 原文` 的内容为准；
2. 原文没有直接回答、或需要整理线索时，才使用 `layer: 第三方解读` 作为补充；
3. 第三方解读与游戏原文冲突时，原文优先，并明确指出存在解读差异；
4. UP 主的分析、考据和推测必须标为“解读”或“推测”，不能改写成官方事实；
5. Copilot 自己推导出的内容也应与原文和第三方观点区分开。

第三方内容建议放在独立目录，并通过 `对应原文` 和 `解析对象` 连接到正式知识条目：

```text
21_第三方解读/
└─ UP 主或主题/
   └─ 视频标题.md
```

### 活动任务的文件结构

活动任务按照地区、版本或活动主题分组；有系列关系的任务继续放入系列文件夹：

```text
06_活动任务/
└─ 地区、版本或活动主题/
   └─ 系列任务/
      ├─ 系列任务.md
      ├─ 01. 第一项任务.md
      ├─ 02. 第二项任务.md
      └─ 03. 第三项任务.md
```

系列文件夹本身不需要编号。编号只用于表示系列内任务的阅读顺序，任务文件使用 `01.`、`02.`、`03.` 等前缀。没有明确系列关系的活动内容，可以直接放在对应的地区、版本或活动主题文件夹中，不人为添加不存在的任务编号。

系列任务页是导览页，正文中的任务列表使用 Obsidian 双链指向具体任务文件；具体剧情仍以编号任务文件为准。

### 补充资料

NPC 对话、角色场景与访客对话、互动文本、物品描述、短信、梦境护照、如我所书、模拟宇宙档案与过场提示，补充任务正文之外的剧情。

完整重复的文本通过导览链接到已有笔记；部分重复的段落链接回已有原文，其余内容保留在补充条目中。资料中的版本、触发条件和选项分支应结合正文阅读。

“设定资料导览”只提供阅读入口，编辑考据与推测不能提升为游戏事实。

## 四、Front Matter

### 公共字段

大多数知识条目使用以下字段：

```yaml
游戏: "崩坏：星穹铁道"
layer: "原文"          # 原文、导览或第三方解读
type: "任务原文"
涉及实体: []            # 正文中出现并建立双链的相关实体
```

`layer: 原文` 表示正文资料；`layer: 导览` 表示系列任务等索引页面。`type` 用于区分内容类型，`涉及实体` 用于从人物、地点、物品、任务、派系和其他设定之间建立检索关系。

### 第三方剧情解读

B 站视频转写或整理后的剧情解读使用独立的类型和来源字段。它们用于引导检索、串联线索和补充理解，不与官方原文混合：

```yaml
游戏: "崩坏：星穹铁道"
layer: "第三方解读"
type: "剧情解读"
权威等级: 2
来源平台: "哔哩哔哩"
来源UP主: ""
视频标题: ""
来源链接: ""
解读性质: ["事实整理", "分析", "推测"]
解析对象: []
对应原文: []
涉及实体: []
```

`权威等级: 2` 表示它低于游戏原文的一级；游戏原文为最高依据。`解析对象` 用于说明解读针对的任务、角色、地区、派系或设定，`对应原文` 用于指向库内可以核对的官方文本。无法确认的内容应保留为分析或推测，不要写成确定事实。

第三方解读正文开头建议保留醒目的说明：

```markdown
> [!warning] 权威性说明
> 本文是 B 站 UP 主的剧情解读，不是游戏原文。涉及事实时优先以 `layer: 原文` 的笔记为准；本文中的分析和推测仅作辅助参考。
```

为了方便 Copilot 使用，正文最好分开写“核心观点”“原文依据”“解读与推测”，并在“原文依据”中链接对应的游戏文本。

### 任务原文

```yaml
任务类型: "开拓任务"
所属地区: []
版本实装: ""
开放等级: ""
任务条件: ""
所属系列: ""
任务编号: ""
涉及角色: []
相关道具: []
相关成就: []
前置任务: []
后续任务: []
```

崩铁任务类型按库内实际分类记录，不强制合并为其他游戏的分类。任务之间的前置、后续关系以及所属系列关系使用双链或结构化字段保存。

任务正文通常包括任务描述、任务剧情、任务步骤、旁白、角色对话、玩家选项、分支剧情和提示。

### 角色故事与角色语音

角色故事记录角色介绍、背景、经历和其他设定文本；角色语音按语音类型分组保存，重点保留角色台词。

常见字段包括：

```yaml
所属角色: ""
命途: ""
武器类型: ""
实装版本: ""
```

### 书籍原文

书籍保留游戏内可阅读的原文。单卷书籍直接成文；书架合集按篇或卷拆分，每一篇单独成文，并通过书名、卷数、卷名和涉及实体与其他条目关联。

```yaml
书名: ""
卷数: ""
卷名: ""
```

### 光锥与遗器故事

光锥文件保留光锥剧情文本和副标题；遗器文件保留各部件的名称、描述和故事。攻击力、技能数值、套装效果、获取方式等攻略数据不作为故事正文保存。

### 模拟宇宙与差分宇宙内容

- 奇物：记录奇物的介绍与世界观信息；
- 事件：记录事件描述、玩家选项、效果和分支对话；
- 权杖：记录不可知域权杖的背景与故事；
- 方程：记录差分宇宙方程的演绎、推演和相关文本。

模式、实装版本、命途、相关事件等信息放在 Front Matter 或正文的结构化位置；战斗数值和纯攻略效果不作为知识库的主要内容。

### 世界观词条

派系、星神、专有名词等大型条目可以按章节拆分为多个文件。拆分后的文件使用 `词条`、`章节`、`条目` 和 `涉及实体` 等字段标明来源与层级；开篇总览在有需要时单独保存。

### 敌对物种

敌对物种文件主要保留名称、背景、介绍和世界观关联。抗性、技能、掉落材料等战斗数据不属于故事正文。

## 五、正文与链接约定

- 角色对话使用 Markdown 列表或加粗角色名表示；
- 玩家选项使用 `> **[玩家选项]**：…`；
- 效果、提示和分支剧情使用引用块或对应的小标题表示；
- 任务、人物、地点、物品、派系、星神和其他知识条目之间优先使用 `[[页面名]]` 双链；
- `{RUBY_B#注音}文{RUBY_E#}` 转为 `文（注音）`，`{F#甲}{M#乙}` 转为 `甲/乙`；
- 网页模板、查询语句、导航模板和排版标记转换为可直接阅读的 Markdown 文本；
- 正文尽量保持源资料的叙事顺序和原意，不额外加入未经标注的剧情推断。

## 六、使用方式

可以从目录按内容类型浏览，也可以从系列任务导览页进入具体任务。进行检索时，通常可以结合以下字段和关系：

- `type`：按任务、角色、书籍、光锥、遗器、模拟宇宙或世界观条目筛选；
- `所属系列`、`任务编号`：还原任务线和阅读顺序；
- `涉及角色`、`涉及实体`、`相关事件`：查找人物、地点、物品和事件之间的关联；
- `版本实装`、`所属地区`、`模式`：按时间、地点或游戏模式定位内容；
- `词条`、`章节`、`条目`：定位大型词条拆分后的具体内容；
- `layer: 第三方解读`：查找辅助性分析，再回到 `layer: 原文` 核对事实。
